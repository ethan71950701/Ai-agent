# FCM 喚醒實驗（2026-11-19）

目的：驗證「接收端 App 沒開著」時，能不能用 FCM 高優先級資料訊息叫醒它，作為「手機對手機互傳不用常駐」的第一步。

## 結果（使用者在自己的手機上實測）
- App 在背景：瞬間收到。
- App 從最近工作清單滑掉：**一開始收不到**。原因是手機系統（看起來是小米／HyperOS 類）把滑掉當成強制停止，並拒絕了好幾次「自啟動」。
- 把 Vertex 的「**自啟動**」打開之後：滑掉、鎖屏都收得到，延遲大約幾百毫秒。
- 結論：**技術上可行，但使用者必須在手機上開「自啟動」（並把電池設成無限制）**；不同廠牌名稱與成功率不同，別人的手機不保證。

## 這次實驗的做法（實驗程式不在 main，在 `claude/project-review-continue-qsyt5j` 分支的 commit 9371c41）
- Firebase 專案由使用者自己建（Spark 免費方案），`google-services.json` 在執行時由使用者選檔，存 App 私有資料夾，不進 repo、不用 google-services 外掛。
- 發送端用服務帳戶金鑰簽 JWT 換 access token，呼叫 FCM HTTP v1 送 `priority: high` 的 data 訊息；用完要刪金鑰。
- 接收端 `FcmLabService` 收到就跳通知並寫 `LifeLog`（含延遲、原優先級與實際優先級）。

## 還沒做／要決定
- 這只證明「叫得醒」。互傳要再接：A 臨時開接收服務 → 推播告訴 B「A 在這個位址等你」→ B 被叫醒後連過去拿。推播只當門鈴，真正驗證仍用配對簽章，不能把推播當授權。
- 金鑰：個人使用可放發送端手機（用 Android Keystore 加密）；要給別人用就要有雲端代發（要查費用與方案）。
- 要在 App 裡教使用者開「自啟動」與電池無限制，並偵測收不到的情況。
- 高優先級推播有配額；每次喚醒最好都有使用者看得到的通知。
- 只在同一個區網有效（檔案仍走區網直連）。

狀態：🟡 實驗成功；正式功能尚未開始。
